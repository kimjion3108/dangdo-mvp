# DANGDO · 실제 주변 탐색

## v0.3 · GPS와 AI 식당 추천

배포: https://kimjion3108.github.io/dangdo-mvp/

첫 화면은 실제 지도 기반 식당 탐색입니다. 현재 위치는 사용자가 버튼을 누르고 브라우저 위치 권한을 허용할 때만 가져옵니다. GPS 좌표를 로컬 저장소에 보관하지 않으며 검색 좌표는 지도·장소 제공업체에 전송됩니다.

- 기본 지도: Leaflet + OpenStreetMap. Overpass API에서 실제 음식점·카페를 검색합니다. 반경 500m / 1.5km / 3km, 지도 이동 후 재검색, 목적지 검색(Nominatim), 저장 기능을 지원합니다. 식당 목록은 공개 데이터의 지역별 등록 범위에 따라 다릅니다.
- 카카오맵: 설정에 **JavaScript 키**를 입력하면 Kakao Maps JS SDK와 Places 검색으로 전환합니다. 카카오 개발자 콘솔에서 카카오맵 사용 설정을 확인하고 `https://kimjion3108.github.io`를 JavaScript SDK 도메인으로 등록해야 합니다. 키는 브라우저별 설정입니다. REST API 키·Admin 키를 넣으면 안 됩니다.
- 길찾기: 실제 장소 좌표를 카카오맵 도보·자동차·대중교통 링크로 전달합니다. GPS가 없으면 선택한 검색 중심점을 출발지로 사용합니다. 카카오 T 탑승·ETA는 자동 연동하지 않습니다.
- AI: `Xenova/paraphrase-multilingual-MiniLM-L12-v2`의 q8 모델을 Transformers.js로 Web Worker에서 실행합니다. 사용자가 실행 버튼을 누른 뒤 모델을 다운로드하며, 첫 실행은 네트워크와 기기에 따라 시간이 걸립니다. 한국어 요청과 실제 장소 이름·업종의 코사인 유사도(85%)와 거리 점수(15%)를 합산합니다. 최대 30개를 비교합니다. 생성형 리뷰·메뉴·평점은 만들지 않습니다. 혼잡도·영업 여부·가격·알레르기는 검증하지 않습니다.
- 기존 혜택·주문·정산 시연은 설정 메뉴에 보존했습니다. 실제 식당에 가상 가격이나 결제 기능을 붙이지 않았습니다.

위치 거부, 빈 검색 결과, 네트워크 오류, AI 로딩 실패/취소 상태를 제공합니다. 공개 API에는 이용량 제한과 장애 가능성이 있습니다. API 키가 없는 상태에서는 **카카오 지도 타일·카카오 장소 검색은 활성화되지 않습니다.**

### 개발 및 배포

```sh
ONNXRUNTIME_NODE_INSTALL_CUDA=skip npm ci
npm run dev
npm test
npm run build -- --base=/dangdo-mvp/
```

AI는 브라우저 WASM을 사용하므로 Node CUDA 설치가 필요 없습니다. `.github/workflows/pages.yml`은 `main` 커밋마다 테스트·빌드 후 GitHub Pages로 배포합니다. 비밀 API 키를 정적 번들에 넣지 마세요.

# DANGDO MVP

## v0.2 · 브랜드 비용과 정산

상단 **브랜드** 화면을 추가했습니다. 캠페인 운영비·유효 구매당 성과 비용·할인 및 포인트 지원 예산을 분리하고, **가맹점 → 이번 시연 정산**에서 비용 부담자와 예상 정산액을 확인합니다. 픽업 전 주문 취소, 잔액·포인트·예산 복원, 픽업 완료 후 성과 비용 인정을 지원합니다. 가격과 비용률은 검증 전 가정입니다. 상세 계약안과 계산 예시는 [BUSINESS_MODEL.md](BUSINESS_MODEL.md)를 참고하세요.

거래·정산 검증은 현재 `npm test` 10개입니다. `.github/workflows/ci.yml`은 GitHub 업로드 후 테스트와 빌드를 자동 확인하도록 준비했습니다. Sites 배포 주소는 실제 배포 성공 후 안내하며 GitHub 계정 연결은 별도입니다.

카카오 T 목적지·ETA → 도착 혜택 → 카카오페이 mock 결제 → 할인·포인트 → 가맹점 성과를 연결한 모바일 웹 PoC.

## 실행

Node.js 20.19+ 또는 22.12+ 환경에서:

```sh
npm install
npm run dev
```

http://127.0.0.1:5173 에서 실행됩니다. `npm run build`는 배포용 `dist/`를 만들고 `npm test`는 거래 무결성 검증을 실행합니다. 데스크톱은 시연 컨트롤과 모바일 앱을 함께, 휴대폰 크기는 앱을 전체 화면으로 표시합니다.

## 시연 순서

1. 성수역·8분 상태에서 첫 번째 커피 혜택 선택.
2. 상세 바텀시트에서 혜택 받고 결제하기 → 픽업 안내 확인 → 3,000원 mock 결제.
3. 결제 완료: 할인 1,500원, 포인트 150P, 잔액 243,344원 확인.
4. 상단 가맹점 전환: 오늘의 매출 54,600원, 결제 13건 확인. 기본값 51,600원·12건은 예시 데이터.
5. 주문 관리 → 준비 완료 알림 → 픽업 완료 처리. 사용자 주문 내역에도 반영.
6. 시연 설정: ETA 18분(노출 전), 도착(픽업), 다음 결제 실패·재시도, 초기화. 모바일 설정은 상단 조절 아이콘.
7. 목적지 변경: 서울숲은 별도 혜택 2곳, 광화문은 빈 상태. 카테고리 필터와 브라우저 재실행 후 주문·포인트 복원 지원.

## 구현 범위

- 목적지와 ETA는 시연 입력입니다. 실제 카카오 T API, 위치 수집, ETA 예측, AI 추천 서버는 연동하지 않았습니다.
- 결제·잔액·리워드는 브라우저 안의 mock입니다. 실제 카카오페이 승인·인증·송금은 발생하지 않습니다.
- 주문과 포인트는 이 브라우저의 localStorage에 저장됩니다. 가맹점과 사용자는 같은 앱의 상태를 공유합니다. 여러 브라우저·여러 사용자의 서버 동기화는 없습니다.
- 가맹점 기본 성과는 고정 예시이며 시연 주문의 결제 금액·할인·포인트가 해당 가맹점에만 더해집니다. 노출·선택 수와 전환율은 예시 기반입니다.
- 픽업 알림은 앱 상태 전환이며 외부 푸시가 아닙니다. 주문 번호는 시연용으로 매장 인증 코드가 아닙니다. 안내하는 30분 픽업 기간의 실제 만료·환불 처리는 구현하지 않았습니다.
- 금액의 단일 계산, 재고·ETA·목적지 검증, 승인 ID 중복 방지, 같은 이동의 같은 상품 중복 결제 방지가 있습니다.
- 초기화는 시연 주문·포인트·설정을 모두 초기화합니다. v0.2는 픽업 전 mock 주문 취소·잔액 환원·포인트 회수를 지원합니다. 실제 PG 취소/환불과 로그인은 구현하지 않았습니다.
- 카카오 공식 앱이나 제휴 서비스가 아닌 독립 PoC임을 시연 화면에 표시했습니다.
- Noto Sans KR는 Google Fonts에서 로드하며 로딩 실패 시 시스템 한글 글꼴로 표시합니다.

## 파일

- `src/main.jsx`: 사용자·가맹점 화면과 시연 상태 전환
- `src/style.css`: 반응형 화면, 다크 페이 UI, 바텀시트
- `src/model.js`: 혜택 데이터, 자격·금액·주문·성과 계산
- `tests/payment.test.js`: 결제·중복 승인·자격·성과 분리·복원 검증

프로젝트 `sources/`와 동기화 파일은 수정하지 않았습니다.
